Preface

This version of the paper simply translates the text from LaTeX to HTML. There have been some minor content changes due the change in format, for example the "double-ended purple arrows" are now multiple purple arrows, so this language has been updated.

I had originally envisioned placing the code samples to the side of the prose, but this turned out to not make much sense. It would work well if the text referencing the code sections was both longer than the code itself and together they took up more than one screen's worth of space but this is not the case in the current draft of the paper.

The full contents of footnotes and citations can be viewed by hovering over the asterisk or parenthesized nickname respectively. I decided to use nicknames for citations so that it was clear where I was drawing my information from prior to hovering without being too disruptive to the text. As a point of comparison, an historian who is citing another's work would use the last name of the author to identify where they were sourcing their information from. This allows the reader to get an approximation of the quality and variety of the work's sources at a glance, while full information is provided at the end if they want to delve deeper. Engineering papers traditionally refer to sources with simple numerals. This communicates practically no information at a glance, and humans are not particularly good at remembering elements of a list merely by their numeric index. Providing a nickname provides more information more quickly and serves as a memory aid to the human reader. This is strictly better than the traditional method.

The next draft will add a description of Bash and start work on the analysis section. It migh seem premature to start analysis before all of the descriptions are complete. However, I already have some thoughts about how the features provided by different languages can supplement or supercede each other and I'd like to get them written down sooner rather than later. Additionally, starting on this section helps guide my descriptions productively because it helps focus my attention on the details that will be most relevant instead of simply describing every detail I can find. It also helps my subconscious work on the analysis while I am writing the descriptions by giving it something concrete to reason about.
